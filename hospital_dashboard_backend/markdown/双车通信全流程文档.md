## 一、系统架构与两车定位

```
HIS(:3001)                    大屏后端(:8080)                   车1 ROS / 车2 ROS
┌──────────┐  POST/DELETE  ┌──────────────┐  WebSocket       ┌─────────────────┐
│ 药师扫码  │ ───────────→ │ workflow.py  │ ──── /rxzy_msg ──→ │ 车1 (取药)      │
│ 护士扫码  │              │ his_sender   │    /car01_pub ←──  │ :9090           │
│ 删除处方  │              │ ros_listener │                    └─────────────────┘
└──────────┘              │              │  WebSocket       ┌─────────────────┐
                          │              │ ── /car02_rxzy_msg → │ 车2 (跨梯送达)  │
                          │              │    /car02_pub ←──    │ :9090           │
                          └──────────────┘                    └─────────────────┘
```

| 维度 | 车1（取药车） | 车2（送药车，跨梯） |
|------|-------------|-------------------|
| IP/端口 | 192.168.51.43:9090 | 192.168.51.16:9090 |
| 系统订阅 Topic | `/car01_pub` | `/car02_pub` |
| 系统发布 Topic | `/rxzy_msg` | `/car02_rxzy_msg` |
| 通信范式 | **逐药品四阶段握手**（start→running→end，顺序串行） | **事件驱动 4 信号**（连发+回执停） |

## 二、完整通信主线（箭头流）

```
医生开方(approved)
  │
  ▼ 车1 sender 主循环取单
系统→车1: start(药1坐标) ──2s重发──▶ 车1回 running-started → N2+语音
系统→车1: running(药1坐标) ──2s重发──▶ 车1回 step5-waiting-end
系统→车1: end×2(药1坐标) ──────────▶ 阶段4 等3秒
  │
  ▼ for循环 药2（同上四阶段）
系统→车1: start(药2坐标) → running → end×2 → 等3秒
  │
  ▼ 车1 末药完成，上报收尾消息
车1→系统: arm_end → N4完成+N5进行中
车1→系统: all_completed → 停止发送+语音×2
车1→系统: 药单级end → HIS处方置dispensed
  │
  ▼ HIS 药师节点3 全部追溯码扫码出库
HIS→后端: POST /pharmacist-success-trigger
  ├─→ 系统→车2: {code}_pharmacist-success（连发，2s/次）
  └─→ 系统→车1: pharmacist-success（结构化9字段，单发+失败重试3次）
  │
  ▼ 车2 收到 pharmacist-success，抵达电梯
车2→系统: {code}_lift-arrive → N7
  │
  ▼ 电梯8步编排（Step0-Step8）
Step0: 停①pharmacist-success
Step1: 电梯开门 → N8
Step2: 系统→车2: {code}_lift-across（连发） → N9
Step3: 等5秒（车2进梯）
Step4: 电梯关门 → N10
Step5: go_floor(4楼) → 等floor_arrived → N11
Step5.5: 到站开门 → N12
Step6: 系统→车2: {code}_lift-open（连发） → N12
  │
  ▼ 车2 到达护士站
车2→系统: {code}_nurse_arrive → 语音"药物已送达请您确认" + N14
  │（注：nurse_arrive 仅触发语音，不解锁 Step7）
  │
  ▼ HIS 护士节点4 全部追溯码扫码确认
HIS→后端: POST /nurse-success-trigger → 阶段校验(N12必须存在)
  → trigger_nurse_arrive_event() → 解锁 Step7
Step7: 解除等待
Step8: 停⑦lift-open → 系统→车2: {code}_nurse-success×3 → N15
  │
  ▼ 处方完成
```

## 三、车1 通信详情

### 3.1 任务启动

后端主循环每 2s 轮询 HIS MySQL：

```sql
SELECT prescription_code, id, created_at FROM prescriptions
WHERE status = 'approved' ORDER BY created_at DESC LIMIT 1
```

查到新处方时：重置药品状态 → 查药品坐标(4表联查) → 记 N1 → 首药发前记 N3 → 进入逐药品 for 循环。

**防护机制**：
- **重入防护**：`workflow_events` 已有 N5 事件 → 跳过药品发送（防重启后重复发 start）
- **删除重下自愈**：`created_at` 与旧事件时间不一致 → 自动清空旧事件后正常发 start
- **失败集合**：单药品超时放弃 → 该处方进失败集合，直到新处方到来

### 3.2 单药品四阶段握手

```
阶段1  系统→车1: start（2s重发，上限15次）  ──▶  等回执: {id}_{code}_running-started
阶段2  系统→车1: running（2s重发，上限15次） ──▶  等回执: {id}_{code}_step5-waiting-end
阶段3  系统→车1: end×2（间隔2s，不等回执）         ← step5回执后立即发
阶段4  等3秒 → for循环取下一药品
```

> **重发上限 ≠ 等待上限**：15次×2s=30s 重发窗口到达后停止发送，但继续静默等待回执最长 300s（每 30s 打印心跳）。真实车1 导航+抓药+放药实测超 43s，远超 30s 窗口。

#### 系统→车1 消息格式（start/running/end/pharmacist-success 共用）

```json
{
    "op": "publish",
    "topic": "/rxzy_msg",
    "msg": {
        "data": "start | running | end | pharmacist-success",
        "prescription_code": "012026083100124",
        "medicine_id": 1,
        "x": 1.5, "y": 2.0, "z": 0.0, "yaw": 0.0,
        "medicine_total": 2,
        "medicine_index": 1
    }
}
```

| 字段 | 说明 |
|------|------|
| `data` | 命令类型 |
| `prescription_code` | 15位处方编号 |
| `medicine_id` | 当前药品 ID |
| `x/y/z/yaw` | 药品在药房的抓取坐标（medicine_locations 表） |
| `medicine_total` | 处方药品总数 |
| `medicine_index` | 当前药品序号（从 1 开始） |

#### 车1→系统 回执格式

统一格式：`{medicine_id}_{prescription_code}_{status}`（药品级）或 `{prescription_code}_{status}`（药单级，无 medicine_id 前缀）。

**驱动握手的回执**：

| 回执消息 | 触发动作 | 15节点 |
|---------|---------|--------|
| `{id}_{code}_running-started` | 双重校验(处方码+药品ID) → 置 started_event，解锁阶段2 | N2 + 语音 car_can_go |
| `{id}_{code}_running-step5-waiting-end` | 双重校验 → 置 step5_event，解锁阶段3 | — |
| `{code}_arm_end`（药单级） | 补记 N1-N3 → N4 完成 → N5 进行中 | N4→N5 切换 |
| `{code}_all_completed`（药单级） | 停止发送 + 语音×2 | N4 + 语音 |
| `{code}_end`（药单级） | HIS 处方状态→dispensed | — |

**机械臂过程消息**：

| 消息 | 含义 | 15节点 |
|------|------|--------|
| `{id}_{code}_arm-picking` | 机械臂抓取中 | N4 detail |
| `{id}_{code}_arm-placing` | 机械臂放药中 | N4 detail |
| `{id}_{code}_arm-error` | 机械臂异常 | N4 detail |

**过程状态消息**（仅更新展示，不进 15 节点事件）：

| 消息 | 展示语义 |
|------|---------|
| `running-step1-navigate-to-pharmacy` | 前往药房中 |
| `running-step2-pick` | 抓药中 |
| `running-step3-deliver-medicine` | 放药中 |
| `running-step4-navigate-doctor` / `skip-doctor` | 前往确认点 / 跳过 |
| `running-step5-return` / `skip-return` | 返回原点 / 跳过 |
| `error-step*` | 各步骤错误（只更新展示，不中断握手） |

### 3.3 一单两药的切换逻辑

```
药A(idx=0): start→running-started→running→step5→end×2→等3秒
                                                              │
                                                              ▼  for循环 idx+1
药B(idx=1): start→running-started→running→step5→end×2→等3秒
                                                              │
                                                              ▼  循环结束
等待车1 上报 arm_end / all_completed / 药单级end 收尾
```

**切换要点**：药品间切换由 for 循环驱动，不依赖药师扫码。`started_event`/`step5_return_event` 在每个药品处理开始时 `clear()`，保证回执隔离。

### 3.4 pharmacist-success（系统→车1）

**触发**：HIS 节点3 全部追溯码扫码出库完成（`total>0 && outbound==total`）→ `POST /pharmacist-success-trigger`

**发送方式**：单发 + 失败重试最多 3 次（间隔 2s），成功即停。与车2 连发模式不同——车1 无回执停止机制，连发会无限刷屏。

**消息格式**：与 start 完全一致（9 字段结构化），`data="pharmacist-success"`。药品字段取车1 当前处理中的药品上下文，无上下文时 medicine_id=0、坐标=0.0。

## 四、车2 通信详情

### 4.1 信号总览

4 个系统→车2 信号，均为**连续发送**模式（每 `CAR2_SIGNAL_INTERVAL=2` 秒重发一次）：

```
① 系统→车2: {code}_pharmacist-success   连发，HIS 节点4 扫码确认后停（经 lift-arrive 编排）
② 车2→系统: {code}_lift-arrive           单次（触发电梯8步编排）
③ 系统→车2: {code}_lift-across           连发，lift-open 启动时切换停
④ 系统→车2: {code}_lift-open             连发，HIS 节点4 扫码确认后停
⑤ 车2→系统: {code}_nurse_arrive           单次（仅触发语音+N14，不解锁 Step7）
⑥ 系统→车2: {code}_nurse-success         固定发 3 次自动停
```

### 4.2 各信号详情

#### ① pharmacist-success（系统→车2，连发）

| 项 | 内容 |
|---|------|
| 触发 | HIS 节点3 全部扫码出库 → `POST /pharmacist-success-trigger` |
| 格式 | `{prescription_code}_pharmacist-success`（纯字符串 data） |
| 停止 | 车2 回报 `lift-arrive` → 编排 Step0 停止 |
| 15节点 | 触发 N6 任务下发 |

```json
{ "op": "publish", "topic": "/car02_rxzy_msg", "msg": { "data": "012026083100124_pharmacist-success" } }
```

#### ② lift-arrive（车2→系统）

| 项 | 内容 |
|---|------|
| 触发 | 车2 抵达电梯 |
| 格式 | `{prescription_code}_lift-arrive` |
| 系统动作 | 停① → 触发8步电梯编排 → 记 N7 |

#### ③ lift-across（系统→车2，连发）

| 项 | 内容 |
|---|------|
| 触发 | 电梯编排 Step2（开门后） |
| 格式 | `{prescription_code}_lift-across` |
| 停止 | lift-open 启动时自动切换停止 |
| 15节点 | N9 跨梯运输 |

```json
{ "op": "publish", "topic": "/car02_rxzy_msg", "msg": { "data": "012026083100124_lift-across" } }
```

#### ④ lift-open（系统→车2，连发）

| 项 | 内容 |
|---|------|
| 触发 | 电梯到达目标楼层 + 到站开门完成（Step5.5） |
| 格式 | `{prescription_code}_lift-open` |
| 停止 | HIS 节点4 扫码确认 → `trigger_nurse_arrive_event()` → Step7 解锁 → Step8 停止 |
| 15节点 | N12 开门送出 |

```json
{ "op": "publish", "topic": "/car02_rxzy_msg", "msg": { "data": "012026083100124_lift-open" } }
```

> **与直觉不同**：lift-open 的停止不是由车2 `nurse_arrive` 消息触发，而是由 HIS 节点4 扫码确认 API 触发。这是为了避免依赖车2 ROS 消息的可靠性。

#### ⑤ nurse_arrive（车2→系统）

| 项 | 内容 |
|---|------|
| 触发 | 车2 到达护士站 |
| 格式 | `{prescription_code}_nurse_arrive` |
| 系统动作 | **仅**记录日志 + 语音播报"药物已送达请您确认"（连播2次）+ 记 N14 |
| **不**触发 | 不 set `_nurse_arrive_event`，不解锁 Step7，不触发 nurse-success |

#### ⑥ nurse-success（系统→车2，固定 3 次）

| 项 | 内容 |
|---|------|
| 触发 | HIS 节点4 全部追溯码确认 → `POST /nurse-success-trigger` → 阶段校验(N12 必须存在) → 幂等去重 |
| 格式 | `{prescription_code}_nurse-success` |
| 停止 | 固定发 3 次自动停止，无外部回执依赖 |
| 15节点 | N15 任务完成 |

```json
{ "op": "publish", "topic": "/car02_rxzy_msg", "msg": { "data": "012026083100124_nurse-success" } }
```

### 4.3 电梯8步编排（lift-arrive 触发）

| 步骤 | 动作 | 15节点 |
|------|------|--------|
| Step0 | 停① pharmacist-success + 清除护士到达信号 | — |
| Step1 | 电梯开门（TCP `open_door`，等 ACK + 3s） | N8 |
| Step2 | 启动③ lift-across 连发 | N9 |
| Step3 | 等 5s（车2 进梯） | — |
| Step4 | 电梯关门（TCP `close_door`，等 ACK + 3s） | N10 |
| Step5 | 查层（同层跳过）→ `go_floor`(4楼) → 等 `floor_arrived`（20s 兜底） | N11 |
| Step5.5 | 到站开门（TCP `open_door` + 3s） | N12 |
| Step6 | 启动④ lift-open 连发 | N12 |
| Step7 | 等待 HIS 节点4 扫码确认（`trigger_nurse_arrive_event()` 解锁） | — |
| Step8 | 停④ → 启动⑥ nurse-success×3 | N15 |

## 五、联动触发机制

### 5.1 pharmacist-success 联动（车1 闭环 → 车2 启动跨楼）

```
车1 末药完成 → arm_end → N4→N5 切换
                            ↓
HIS 药师节点3 全部追溯码扫码出库（total>0 && outbound==total）
                            ↓
HIS POST /pharmacist-success-trigger
                            ↓
后端 workflow.py 同一触发点同时向两车发送：
  ├─→ 车2: {code}_pharmacist-success（连发，2s/次）
  └─→ 车1: pharmacist-success（结构化9字段，单发+失败重试3次）
                            ↓
记录 N5 完成 + N6 任务下发
```

**幂等保护**：进程内 `_triggered_pharmacist_success` 集合，同处方仅触发一次。

### 5.2 nurse-success 联动（节点4 确认 → 车2 收尾）

```
HIS 护士节点4 全部追溯码扫码确认（total>0 && confirm==total）
                            ↓
HIS POST /nurse-success-trigger
                            ↓
后端 workflow.py：
  1. 阶段校验：N12_lift_open_sent 必须存在（防药师阶段误触发）
  2. 幂等去重：_triggered_nurse_success 集合
  3. 记录 N13 扫码确认
  4. trigger_nurse_arrive_event() → 解锁 Step7
                            ↓
Step7 解除等待 → Step8 停 lift-open → 发 nurse-success×3 → N15
```

### 5.3 语音播报触发点

| 语音 | 触发消息 | 播报内容 | 次数 |
|------|---------|---------|------|
| car_can_go | 车1 `running-started` | 车辆可以通行 | 每处方 1 次 |
| car_already_arrive | 车1 `all_completed` | 车辆已到达 | 连播 2 次 |
| 药物已送达 | 车2 `nurse_arrive` | 药物已送达请您确认 | 连播 2 次，每处方 1 轮 |
