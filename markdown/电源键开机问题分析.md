# 电源键开机失败问题分析与修复方案

> 更新时间：2026-08-30
> 状态：**已按方案 A 实现代码，待烧录并实测接线/开机行为**
> 关联：电梯IO改版开发文档.md（继电器5 = 电源键 @ GPIO19）

---

## 一、问题现象

- 发送 TCP `power` 命令后：继电器有响应声音（吸合）
- 电梯设备红灯闪一下，随即熄灭
- **设备无法正常开机**

## 二、根因分析（已确认）

修复前，固件 `power_press()` 的实现是**一次性 50ms 短按**：

```
[emission.c:181-188]
relay_on(5)  →  vTaskDelay(50ms)  →  relay_off(5)
   吸合            短暂保持            立即断开
```

- 继电器触点仅闭合 50 毫秒，远不够设备完成开机自检
- 无"电源保持开启"的状态逻辑：吸合后立即释放 = 瞬时通电又断电
- 红灯闪一下即灭，与 50ms 通电窗口的表现完全吻合

**结论：用户的怀疑正确——问题就是继电器只做了瞬时短按，没有持续开启。**

## 三、修复方案与当前实现

### 待确认的关键问题：继电器5 接在哪里？

```
接法A：串在供电回路                 接法B：并接在电源键两端
  电源 ──[继电器触点]── 设备           设备电源键 ──┤
                                       ├──[继电器触点]
  继电器吸合 = 通电                     继电器吸合 = 等效按下电源键
  继电器释放 = 断电                     继电器释放 = 松开电源键
```

### 方案A：持续吸合模式（当前已实现；适用于继电器串在供电回路）

**语义**：继电器 = 电源总开关，吸合即持续供电。

固件改动（emission.c + tcp_client.c）：

```c
/* 新增电源状态 */
static bool power_state = false;

void power_on(void){          // 持续吸合，不释放
    relay_on(5);
    power_state = true;
}
void power_off(void){         // 释放断电
    relay_off(5);
    power_state = false;
}
```

TCP 命令改为两个（或带参数）：

| 命令 | 动作 | ACK |
| --- | --- | --- |
| `power_on` | 继电器5 持续吸合（供电） | ok |
| `power_off` | 继电器5 释放（断电） | ok |
| `power`（保留兼容） | 切换当前状态 | ok，回带当前状态 |

后端 `elevator_control.py` 对应增加 `send_power_on()` / `send_power_off()`。

**注意点**：
- ESP32 重启后 GPIO 默认输出低电平 = 意外断电。需在 `app_init()` 里决定上电默认值（默认开？默认关？）——建议**默认开**（电梯系统上电即供电），或用 NVS 记忆断电前状态
- 继电器长时间吸合：普通信号继电器持续通电吸合是安全的（线圈功耗约 70mW），无问题

### 方案B：长按模式（若并接在设备电源键两端）

**语义**：模拟人手长按电源键（多数设备长按 2~5 秒开机）。

固件改动（emission.c 仅改一处时长）：

```c
void power_press(void){
    relay_on(5);
    vTaskDelay(pdMS_TO_TICKS(3000));   // 50ms → 3000ms（长按3秒，时长待实测）
    relay_off(5);
}
```

- 若设备按一下就能开机（部分设备），则只需延长到 200~500ms
- **无需新命令**，现有 `power` 命令直接可用，改动最小

## 四、如何判断是哪种接法（排查步骤）

1. 断电状态下用万用表量继电器触点两端与设备电源的关系：
   - 若触点断开时设备完全无电、闭合时有电 → 接法A（串在供电回路）
   - 若触点闭合只是短接了电源键两个引脚 → 接法B（并接按键）
2. 或直接试验：手动按住设备物理电源键 3 秒能否开机：
   - 能 → 接法B，用长按方案
   - 设备没有物理按键/只能靠断上电 → 接法A，用持续吸合方案
