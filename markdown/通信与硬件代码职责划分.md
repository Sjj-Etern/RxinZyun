# 通信与硬件代码职责划分

本表只对应《通信与硬件稿子最终版.docx》中展示的代码，不扩展到项目中未在稿件中出现的功能。源代码内以“`【通信工程师负责】`”标识通信工程师需要实现和维护的部分。

## 通信工程师

| 文件 | 负责内容 |
| --- | --- |
| `hospital_dashboard_backend/app/services/his_sender.py` | 查询 HIS 处方及药品坐标；经 rosbridge/ROS 向车1、车2发布任务；管理 Topic 注册、重置、重发与回执同步。 |
| `hospital_dashboard_backend/app/services/ros_listener.py` | 监听和解析车辆 ROS 状态；以状态驱动任务流转；编排车2跨电梯流程。 |
| `hospital_dashboard_backend/app/api/v1/routers/workflow.py` | 接收 HIS 的 HTTP 事件，并转为 `pharmacist-success`、`nurse-success` 等 ROS 调度信号。 |
| `hospital/his/server/src/routes/medicineTraceCodes.ts`（事件桥接函数） | 判断扫码进度或完成状态，并以 HTTP 通知调度后端。扫码校验和状态写入本身不属于通信职责。 |
| `hospital_dashboard_backend/app/services/elevator_control.py` | 响应 UDP 发现；维护与电梯 ESP32 的 TCP 长连接；处理 JSON 命令、ACK 和楼层到达回执。 |
| `elevator_access_control/components/BSP/WIFI/udp_broadcast.c` | ESP32 端 UDP 广播发现，以及后端 TCP 地址和端口的配置接收。 |
| `elevator_access_control/components/BSP/WIFI/tcp_client.c` | ESP32 端 TCP 连接、重连、JSON 指令接收和 ACK 上报；执行动作的代码归硬件工程师。 |

## 硬件工程师

| 文件/模块 | 负责内容 |
| --- | --- |
| `temperature_humidity_sensor/dht11_demo/main/main.c` 及 `components/dht11/` | DHT11 温湿度采集与传感器驱动；稿件中的 WebSocket 上报属于药箱感知链路。 |
| `elevator_access_control/components/BSP/RELAY/` | 电梯开门、关门等继电器执行。 |
| `elevator_access_control/components/BSP/EMISSION/` | 红外 NEC 编码及发射，执行电梯楼层控制。 |
| `elevator_access_control/components/BSP/DHT11/` | 电梯控制板上的温湿度硬件驱动。 |
| `hospital_dashboard_frontend/src/App.vue` | 温湿度数据的大屏展示与定时刷新（稿件中的硬件感知链路展示端）。 |
| `hospital/his/server/src/routes/medicineTraceCodes.ts`（扫码处理路由） | 追溯码校验、药师/护士扫码状态更新及审计记录。 |

## 协作边界

通信工程师定义并维护消息格式、连接、重试、ACK、超时和状态编排；硬件工程师消费这些命令并完成传感、继电器、红外等物理动作后，按约定回传状态。修改跨边界的 JSON 字段、状态值或时序时，两方需要同步更新。
